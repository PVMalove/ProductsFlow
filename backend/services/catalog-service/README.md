# Catalog Service

Независимо разворачиваемый микросервис, отвечающий за **Управление товарами и инвентарем**.

Сервис построен по принципам гексагональной архитектуры со строгим разделением слоев. Реализован паттерн **CQRS**, а логика роутеров сведена к "Тонким эндпоинтам", которые занимаются исключительно трансляцией HTTP-протокола. Разделяемые примитивы импортируются из `backend/libs/`.

## Ключевые обязанности
- **Лента товаров**: Курсорная (keyset) пагинация списков, публичная видимость (три независимых правила: `is_active` товара, `is_active` владельца, наличие валидного токена), жизненный цикл товара (создание, `PATCH`-обновление, активация/деактивация, удаление).
- **Управление медиа**: Картинка товара — MinIO, приватный bucket, стабильный ключ `products/{id}/image`; клиенту отдаётся временная presigned-ссылка, не публичный URL объекта.
- **Проверка JWT и синхронный fallback**: Подпись токена проверяется через JWKS-кэш (`IdentityClient`, `kernel-platform`). На холодном старте локальной read-модели и на админской ветке catalog делает единственный синхронный HTTP-вызов к `identity-service` (`GET /api/v1/users/me`); при недоступности identity админские действия отвечают `503`, обычные пользователи не затронуты.
- **Асинхронная хореография**: Локальный воркер (`catalog-worker`) слушает RabbitMQ на события `user.*.v1` от `identity-service` (включая `user.deleted.v1`), чтобы версионированным upsert обновить `owner_read_model` и скрыть товары деактивированного/удалённого владельца.

## Архитектурные особенности
- **Идентификаторы**: `UUIDv4` для всех ключей — предотвращает IDOR-уязвимости и скрывает бизнес-метрики.
- **BFF Контракты**: Ответы API строго следуют унифицированной структуре оболочки `data`/`meta`/`error`.
- **Запуск**: Схема БД и bucket'ы MinIO инициализируются строго за пределами хука `lifespan` FastAPI, через изолированный bootstrap-контейнер, до старта `catalog-api`.

## Команды разработчика

Все задачи выполняются через глобальный `Makefile` (Polyrepo), чтобы гарантировать использование правильного виртуального окружения (`uv.lock`):

```bash
# Запуск линтеров, форматтеров и статической типизации
make check pkg=catalog-service

# Запуск децентрализованных локальных юнит- и интеграционных тестов
make test pkg=catalog-service

# Автогенерация новой миграции БД
make db-revision pkg=catalog-service msg="add products table"
```

## Запуск

### Запуск через Docker (Production/Full Stack)
Весь стек (БД, брокеры, S3, все сервисы и Gateway) поднимается единой командой из корня ackend/:
``bash
make up_prod
``

### Локальный запуск (Разработка)
Для локальной отладки без Docker необходима инфраструктура и запущенный identity-service, откуда Catalog скачивает JWKS публичные ключи при старте.

1. Из корня ackend/ запустите PostgreSQL, RabbitMQ и MinIO:
   ``bash
   make up_dev
   ``
2. Скопируйте .env.example в .env внутри директории catalog-service.
3. **Важно:** измените адрес Identity в .env, чтобы локальный процесс мог скачать ключи (так как имя identity-api в локальной сети недоступно):
   ``env
   CATALOG_IDENTITY_BASE_URL=http://localhost:8001
   ``
4. Убедитесь, что identity-service уже запущен на порту 8001.
5. Находясь в директории catalog-service, примените миграции базы данных:
   ``bash
   uv run alembic upgrade head
   ``
6. Запустите сервис локально на порту 8002:
   ``bash
   uv run uvicorn src.api.main:app --port 8002 --reload
   ``
Swagger сервиса будет доступен по адресу: [http://localhost:8002/docs](http://localhost:8002/docs)
