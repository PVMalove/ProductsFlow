# Catalog Service

Независимо разворачиваемый микросервис, отвечающий за **Управление товарами и инвентарем**.

Сервис построен по принципам гексагональной архитектуры со строгим разделением слоев. Реализован паттерн **CQRS**, а логика роутеров сведена к "Тонким эндпоинтам", которые занимаются исключительно трансляцией HTTP-протокола. Разделяемые примитивы импортируются из `backend/libs/`.

## Ключевые обязанности
- **Лента товаров**: Пагинированный список товаров, read-модели и жизненный цикл товара (Активация, Деактивация, Обновление).
- **Управление медиа**: Интеграция с S3-совместимым хранилищем (**MinIO**) для загрузки и хранения изображений товаров.
- **Асинхронная хореография**: Локальный воркер (`catalog-worker`) слушает RabbitMQ на предмет внешних событий (например, `user.deleted` от `identity-service`), чтобы автоматически обновить `owner_read_model` и моментально скрыть товары удаленного пользователя.

## Архитектурные особенности
- **Идентификаторы**: Использует безопасный `UUIDv4` для всех ключей, чтобы предотвратить IDOR-уязвимости и скрыть бизнес-метрики.
- **BFF Контракты**: Ответы API строго следуют унифицированной структуре оболочки `data/meta/error`.
- **Запуск**: Схемы БД и бакеты S3 инициализируются строго за пределами хука `lifespan` FastAPI через изолированные bootstrap-контейнеры.

## Команды разработчика

Все задачи выполняются через глобальный `Makefile` (Polyrepo), чтобы гарантировать использование правильного виртуального окружения (`uv.lock`):

```bash
# Запуск линтеров, форматтеров и статической типизации
make check pkg=catalog-service

# Запуск децентрализованных локальных юнит- и интеграционных тестов
make test pkg=catalog-service

# Автогенерация новой миграции БД
make db-revision pkg=catalog-service msg="add products table"
```
