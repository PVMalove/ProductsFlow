# API

Маршруты товаров живут под `/api/v1/products` (`api/endpoints/products.py`,
`api/endpoints/product_images.py`).

## BFF-конверт ответа (ADR 0002)

Командные эндпоинты товара — создание, обновление, активация, деактивация,
удаление — и query-эндпоинты — чтение, список, аудит — возвращают единый
конверт успеха `{"data": ..., "meta": {}}` (ADR 0002). Эндпоинты картинки
товара следуют тому же контракту: `POST .../image` возвращает `200`, если
картинка заменена, и `201`, если создана впервые — статус выбирается по
флагу `replaced` результата мутации, до построения ответного View. Все
ошибки catalog используют единую структурированную BFF-форму ошибки
(ADR 0003).

## Публичный поиск

`GET /api/v1/products/search?q=<text>` принимает обязательный `q` длиной от 2
до 100 символов и возвращает текстовые совпадения по `name` и `description` в
том же BFF-конверте, что и список Товаров. Некорректный запрос отвечает
стандартным BFF `422 VALIDATION_ERROR` с привязкой к полю `q`.

Поисковая read-model OpenSearch хранит для обоих полей русскую и английскую
анализируемые версии. Имя Товара имеет вес 3, описание — 1; `fuzziness=AUTO`
разрешает опечатки только начиная со слов из трёх символов. Поиск исключает
документы деактивированных Товаров и Товары неактивных Владельцев.
