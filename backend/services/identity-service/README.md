# Identity Service

Независимо разворачиваемый микросервис, отвечающий за **Аутентификацию, Авторизацию и Учетные записи пользователей**.

Сервис построен по принципам гексагональной архитектуры (Ports & Adapters) со строгим разделением на слои (Домен, Приложение, Инфраструктура). Реализован паттерн **CQRS**, а логика роутеров сведена к "Тонким эндпоинтам", которые занимаются исключительно трансляцией HTTP-протокола. Разделяемые примитивы импортируются локально из `backend/libs/`.

## Ключевые обязанности
- **Управление пользователями**: Регистрация, обновление профиля, (де)активация, самостоятельное необратимое удаление (`DELETE /api/v1/users/me` — учётная запись заменяется анонимизированным надгробием, не удаляется физически).
- **Stateless JWT Авторизация**: Генерирует JWT-токены, подписанные приватным ключом RS256, и публикует публичную половину на `GET /.well-known/jwks.json`. `catalog-service` проверяет подпись через этот JWKS-эндпоинт (с кэшем); `support-service` — статически сконфигурированным публичным ключом, без обращения к identity вовсе.
- **Публикация доменных событий**: Единственный producer событий в системе. При мутации пользователя (регистрация, (де)активация, смена роли, удаление) command handler в одной транзакции (Unit of Work) сохраняет строку в `outbox_messages` явным вызовом `drain_events_to_outbox()` — не через ORM-миксин. Локальный воркер (`identity-worker`) асинхронно вычитывает эти строки (`LISTEN/NOTIFY` + polling) и публикует их в RabbitMQ (`productsflow.events`, routing key `user.*.v1`).

## Архитектурные особенности
- **Фреймворк**: FastAPI (Async)
- **База данных**: PostgreSQL (Изолированная логическая БД с собственными миграциями Alembic)
- **Ключи**: Криптографические ключи для генерации токенов хранятся в `backend/secrets/`.

## Команды разработчика

Все задачи выполняются через глобальный `Makefile` (Polyrepo), чтобы гарантировать использование правильного виртуального окружения (`uv.lock`):

```bash
# Запуск линтеров, форматтеров и статической типизации
make check pkg=identity-service

# Запуск децентрализованных локальных юнит- и интеграционных тестов
make test pkg=identity-service

# Автогенерация новой миграции БД
make db-revision pkg=identity-service msg="add users table"
```

## Запуск

### Запуск через Docker (Production/Full Stack)
Весь стек (БД, брокеры, S3, все сервисы) поднимается единой командой из корня backend/:
```bash
make up_prod
```
Swagger будет доступен на порту самого сервиса (см. `docker-compose.yml`); production-стек Gateway не поднимает — он существует только для E2E-тестов (ADR 0004).

### Локальный запуск (Разработка)
Для локальной отладки без Docker необходима запущенная инфраструктура.

1. Из корня backend/ запустите PostgreSQL, RabbitMQ и MinIO:
   ```bash
   make up_dev
   ```
2. Сгенерируйте RSA-ключи (если они ещё не созданы), чтобы Identity мог подписывать JWT:
   ```bash
   make keys
   ```
3. Скопируйте .env.example в .env внутри директории identity-service (порты в нём уже настроены под make up_dev).
4. Находясь в директории identity-service, примените миграции базы данных:
   ```bash
   uv run alembic upgrade head
   ```
5. Запустите сервис локально на порту 8001:
   ```bash
   uv run uvicorn src.api.main:app --port 8001 --reload
   ```
Swagger сервиса будет доступен по адресу: [http://localhost:8001/docs](http://localhost:8001/docs)
