# Identity Service

Независимо разворачиваемый микросервис, отвечающий за **Аутентификацию, Авторизацию и Учетные записи пользователей**.

Сервис построен по принципам гексагональной архитектуры (Ports & Adapters) со строгим разделением на слои (Домен, Приложение, Инфраструктура). Реализован паттерн **CQRS**, а логика роутеров сведена к "Тонким эндпоинтам", которые занимаются исключительно трансляцией HTTP-протокола. Разделяемые примитивы импортируются локально из `backend/libs/`.

## Ключевые обязанности
- **Управление пользователями**: Регистрация, обновление профиля и деактивация.
- **Stateless JWT Авторизация**: Генерирует JWT токены, подписанные ключом RS256. Другие микросервисы *не* делают запросов в identity-service для валидации токенов; они локально проверяют криптографическую подпись, используя публичный ключ.
- **Публикация доменных событий**: При изменении состояния пользователя (например, при удалении аккаунта), сервис транзакционно сохраняет событие `user.deleted` через `OutboxMixin` в PostgreSQL. Локальный воркер (`identity-worker`) надежно пересылает это событие в RabbitMQ для межсервисной хореографии.

## Архитектурные особенности
- **Фреймворк**: FastAPI (Async)
- **База данных**: PostgreSQL (Изолированная логическая БД с собственными миграциями Alembic)
- **Ключи**: Криптографические ключи для генерации токенов хранятся в `backend/secrets/`.

## Команды разработчика

Все задачи выполняются через глобальный `Makefile` (Polyrepo), чтобы гарантировать использование правильного виртуального окружения (`uv.lock`):

```bash
# Запуск линтеров, форматтеров и статической типизации
make check pkg=identity-service

# Запуск децентрализованных локальных юнит- и интеграционных тестов
make test pkg=identity-service

# Автогенерация новой миграции БД
make db-revision pkg=identity-service msg="add users table"
```
