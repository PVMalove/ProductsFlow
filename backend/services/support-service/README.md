# Support Service

Независимо разворачиваемый микросервис, отвечающий за **Службу поддержки, жизненный цикл тикетов и обратную связь**.

Сервис построен по принципам гексагональной архитектуры (Ports & Adapters) со строгим разделением слоев. Реализован паттерн **CQRS**, а логика роутеров сведена к "Тонким эндпоинтам", которые занимаются исключительно трансляцией HTTP-протокола. Разделяемые примитивы импортируются из `backend/libs/`.

## Ключевые обязанности
- **Управление тикетами**: Обрабатывает создание и переходы состояний (State Machine) обращений пользователей (`OPEN` -> `IN_PROGRESS` -> `RESOLVED` -> `CLOSED`).
- **Сообщения**: Управление цепочками сообщений внутри тикета.
- **Асинхронная хореография**: Локальный воркер (`support-worker`) слушает RabbitMQ на предмет внешних событий (например, `user.deleted` от `identity-service`), чтобы автоматически анонимизировать данные пользователя или закрывать брошенные тикеты.

## Архитектурные особенности
- **Transactional Outbox**: Любые мутации состояния агрегата Тикета надежно порождают события через `OutboxMixin`, что гарантирует отсутствие потери данных при временной недоступности RabbitMQ.
- **Тонкие эндпоинты**: Контроллеры в `src/api/` занимаются только маппингом HTTP-структур в `Command/Query` объекты, полностью делегируя выполнение изолированным Хэндлерам, которые ничего не знают об HTTP (`Request`, `Response`).
- **Изолированное тестирование**: Содержит полностью децентрализованные юнит- и интеграционные тесты, проверяющие бизнес-логику строго в границах своего микросервисного контекста.

## Команды разработчика

Все задачи выполняются через глобальный `Makefile` (Polyrepo), чтобы гарантировать использование правильного виртуального окружения (`uv.lock`):

```bash
# Запуск линтеров, форматтеров и статической типизации
make check pkg=support-service

# Запуск децентрализованных локальных юнит- и интеграционных тестов
make test pkg=support-service

# Автогенерация новой миграции БД
make db-revision pkg=support-service msg="add tickets table"
```
