# ProductsFlow

[![CI](https://github.com/PVMalove/ProductsFlow/actions/workflows/ci.yml/badge.svg)](https://github.com/PVMalove/ProductsFlow/actions/workflows/ci.yml)
![Python 3.14](https://img.shields.io/badge/python-3.14-blue)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Сервис учёта товаров на FastAPI: аутентификация пользователей, CRUD-операции над товарами, ролевая модель доступа и полный audit trail всех мутаций.

## Возможности

- **Аутентификация** по JWT (bearer-токен), пароли хешируются `bcrypt`.
- **Роли** `admin`/`user`: администратор видит и может изменять любые товары и учётные записи вне обычных правил владения и видимости.
- **CRUD товаров** с проверкой владения (изменять/удалять/(де)активировать товар может только его владелец или администратор).
- **Деактивация товара** (`is_active`) — обратимое скрытие товара владельцем, независимое от полного удаления (см. [`CONTEXT.md`](CONTEXT.md)).
- **Правила видимости**: анонимные и обычные пользователи не видят деактивированные товары и товары деактивированных владельцев; списки не персонализированы даже для владельца.
- **Курсорная (keyset) пагинация** — списки и поиск товаров устойчивы к вставкам/удалениям между запросами соседних страниц.
- **Audit trail** — неизменяемый журнал создания/изменения/удаления/(де)активации товаров и пользователей с указанием инициатора действия, пишется автоматически на уровне ORM.
- **Поиск и фильтрация**: по названию/описанию, по категории, по диапазону цен — всё с той же курсорной пагинацией.

## Стек технологий

- **Python 3.14**, **FastAPI**, **Pydantic v2**
- **SQLAlchemy 2.0** (async) + **asyncpg**, **PostgreSQL**
- **Alembic** — миграции (применяются автоматически при старте приложения)
- **JWT** (`pyjwt`) + **bcrypt** — аутентификация
- **uv** — управление зависимостями
- **pytest** + **testcontainers** — тесты, включая реальный Postgres в интеграционных тестах
- **ruff**, **mypy**, **vulture** — линт/тайпчекинг/поиск мёртвого кода
- **Docker Compose** — локальное окружение и прод-профиль

## Быстрый старт

Требуется [uv](https://docs.astral.sh/uv/) и Docker (для БД).

```bash
# 1. Установить зависимости
uv sync

# 2. Настроить окружение
cp .env.example .env
# при необходимости отредактировать .env — см. раздел "Переменные окружения"

# 3. Поднять только Postgres (dev-профиль)
make up_dev

# 4. Запустить API локально с автоперезагрузкой
uv run uvicorn app.main:app --reload
```

Приложение само применяет миграции и сидирует БД при старте (см. `app/main.py`). Проверить, что всё поднялось:

```bash
curl http://localhost:8000/health
```

Альтернатива — полностью докеризованный прод-профиль (БД + API одним стеком, API на порту `9000`):

```bash
make up_prod
```

## Переменные окружения

Полный список — в [`.env.example`](.env.example).

| Переменная               | Назначение                                                   |
| ------------------------- | ------------------------------------------------------------- |
| `APP_ENV`                 | Окружение приложения (`dev`/`prod`) — отображается в заголовке API |
| `DATABASE_URL`             | Строка подключения к Postgres (`postgresql+asyncpg://...`)   |
| `SECRET_KEY`               | Ключ подписи JWT                                              |
| `ACCESS_TOKEN_TTL_HOURS`   | Время жизни access-токена, часы                               |
| `ADMIN_PASSWORD`           | Пароль администратора, создаваемого при сидировании БД        |
| `POSTGRES_USER/PASSWORD/DB` | Параметры контейнера Postgres (используются docker-compose)  |
| `POSTGRES_PORT_DEV/PROD`   | Порты, на которые пробрасывается Postgres в dev/prod-профилях |

## API

Полная интерактивная документация (Swagger UI) доступна на `/docs` после запуска приложения, спецификация OpenAPI — на `/openapi.json`.

### Auth

| Метод | Путь             | Доступ    | Описание                    |
| ----- | ----------------- | ---------- | ----------------------------- |
| POST  | `/auth/register`   | публичный | Регистрация пользователя      |
| POST  | `/auth/login`      | публичный | Получение JWT access-токена   |

### Products

| Метод  | Путь                          | Доступ                | Описание                                          |
| ------ | ------------------------------ | ----------------------- | ---------------------------------------------------- |
| GET    | `/products/`                    | публичный (опц. auth)  | Список товаров, курсорная пагинация                  |
| GET    | `/products/search`              | публичный (опц. auth)  | Поиск по названию/описанию                           |
| GET    | `/products/price-range`         | публичный (опц. auth)  | Список товаров в диапазоне цен                       |
| GET    | `/products/category/{name}`     | публичный (опц. auth)  | Список товаров по категории                          |
| GET    | `/products/{id}`                 | публичный (опц. auth)  | Товар по ID (с owner-исключением для деактивированных) |
| POST   | `/products/`                    | авторизован             | Создать товар                                        |
| PATCH  | `/products/{id}`                 | владелец/admin           | Частично изменить товар                               |
| DELETE | `/products/{id}`                 | владелец/admin           | Удалить товар безвозвратно                            |
| PATCH  | `/products/{id}/activate`        | владелец/admin           | Активировать товар                                    |
| PATCH  | `/products/{id}/deactivate`      | владелец/admin           | Деактивировать товар                                  |
| GET    | `/products/{id}/audit`           | владелец/admin           | Audit-лог конкретного товара                         |
| GET    | `/products/audit`                | admin                    | Audit-лог всех товаров                               |

### Users

| Метод | Путь                        | Доступ    | Описание                          |
| ----- | ----------------------------- | ---------- | ------------------------------------ |
| GET   | `/users/`                      | admin     | Список пользователей                |
| GET   | `/users/audit`                 | admin     | Audit-лог всех пользователей         |
| GET   | `/users/me`                    | авторизован | Текущий пользователь                |
| GET   | `/users/me/audit`              | авторизован | Собственный audit-лог                |
| PATCH | `/users/me/password`           | авторизован | Смена пароля                        |
| PATCH | `/users/{id}/activate`         | admin     | Активировать пользователя           |
| PATCH | `/users/{id}/deactivate`       | admin     | Деактивировать пользователя (не себя) |
| GET   | `/users/{id}/audit`            | admin     | Audit-лог конкретного пользователя   |

### Health

| Метод | Путь      | Доступ    | Описание          |
| ----- | ---------- | ---------- | -------------------- |
| GET   | `/health`   | публичный | Проверка живости API |

## Тестирование

```bash
make test       # все тесты (pytest)
make coverage   # тесты + отчёт покрытия (make coverage service=app)
```

Юнит-тесты (`tests/unit/`) не требуют Docker. Интеграционные тесты (`tests/integration/`) поднимают реальный Postgres через `testcontainers` — для них нужен запущенный Docker.

## Архитектура

Слоистая структура: `router → repository → SQLAlchemy model`, с Pydantic-схемами (`app/schemas.py`) в роли границы валидации/ответа. Audit trail пишется декларативно через SQLAlchemy ORM event listeners, а не явными вызовами в бизнес-логике.

Доменная терминология и обоснование ключевых архитектурных решений — в [`CONTEXT.md`](CONTEXT.md) и [`docs/adr/`](docs/adr/):

- [0001 — курсорная пагинация вместо offset](docs/adr/0001-cursor-pagination-product-lists.md)
- [0002 — публичный доступ к спискам, полная видимость только у admin](docs/adr/0002-public-product-listing-admin-visibility.md)
- [0003 — деактивация товара как отдельное поле](docs/adr/0003-product-level-deactivation.md)
- [0004 — audit trail через ORM event listeners](docs/adr/0004-audit-trail-via-orm-events.md)
