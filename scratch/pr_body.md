## Итог
Реализована динамическая сортировка товаров на витрине по новизне и цене (возрастание/убывание) с сохранением эффективной Keyset-пагинации. Добавлен UI-контрол для выбора сортировки.

## Затронутые части проекта
- **catalog-service (backend)**: схемы API, порты приложения, `list_products` query, доменные репозитории, реализация `ProductRepository`.
- **frontend**: страница каталога, компонент `CatalogList`, API клиент и хук для бесконечной прокрутки.

## Бизнес-логика
Пользователи теперь могут сортировать товары на витрине: по умолчанию — "Сначала новые", а также "Сначала дешевые" и "Сначала дорогие". При этом пагинация корректно работает на любых страницах благодаря внедрению составного курсора `(price, id)` или `(created_at, id)`.

## Что изменено
- **Бэкенд**: Введен `CatalogListCursor`, который содержит тип сортировки, значение поля для сортировки и ID товара. `ProductRepository.list` теперь динамически строит `tuple_` условия для keyset-пагинации в зависимости от выбранного столбца и направления (ASC/DESC). Отвязан от `kernel_platform.pagination.Cursor` для избежания нарушения контрактов других сервисов (например, `identity-service`).
- **Фронтенд**: В UI компоненте `CatalogList` добавлен выпадающий список `select`. Выбор сортировки обновляет query-параметры `searchParams` (`?sort=price_asc`), что в свою очередь передается в API запрос `useCursorInfiniteQuery`.

## Проверка
`qa-gate`: PASS.
Функционал покрыт unit и интеграционными тестами бэкенда (`test_product_repository.py`, `test_product_list_contract.py`). На фронтенде обновлены тесты для компонента `CatalogList`. 

## Не проверено и риски
При большом количестве товаров с одинаковой ценой вторичная сортировка по ID работает стабильно. Риски минимальны, так как keyset cursor гарантирует детерминированную выдачу.

## Интеграция
Миграции БД не требуются. Код может быть влит в интеграционную ветку.
