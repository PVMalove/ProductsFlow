# 0001. Cursor-пагинация вместо offset для списков продуктов

`Product` — hard delete без soft-delete/архивного состояния (см. `CONTEXT.md` → «Существование продукта»): строка исчезает из `products` мгновенно и безвозвратно. При `limit/offset`-пагинации это приводит к «дрейфу»: если продукт удаляют между запросами соседних страниц, следующая страница пропускает или задваивает элемент. Выбрали cursor (keyset)-пагинацию по `(created_at, id)` вместо `limit/offset` для всех продукт-list-эндпоинтов (`GET /products`, `/search`, `/price-range`, `/category/{name}`) — курсор по конструкции устойчив к удалениям между запросами.

## Considered Options

- **`limit/offset`** — проще, даёт «прыжок на страницу N» и total count почти бесплатно. Отклонён из-за дрейфа при удалении.

## Consequences

- Курсор — непрозрачный токен, кодирующий `(created_at, id)`; внутренние поля сортировки наружу не выставляются.
- Нет `total`/номеров страниц — только `has_more`/`has_prev`, вычисляемые дешёвым overfetch (`limit + 1` строк). Клиент не может показать «страница 3 из 10» без отдельного запроса.
- Несмотря на выбор cursor, двунаправленная навигация (`after`/`before`) сохранена — в отличие от типичных forward-only лент.
