# 0006. PATCH вместо PUT для частичного обновления товара

`PUT /products/{id}` фактически всегда выполнял частичное обновление: репозиторий (`ProductRepository.update_product`) применяет `ProductUpdate.model_dump(exclude_unset=True)`, то есть непереданные в запросе поля не трогаются. Это расходится с семантикой HTTP-метода `PUT` — клиент должен присылать полное представление ресурса, которым сервер целиком заменяет существующий. Переименовываем эндпоинт в `PATCH /products/{id}`: метод, чья семантика (частичное изменение) и так уже была реализована. `PUT` для этого пути больше не зарегистрирован и отвечает `405 Method Not Allowed`. Заодно `ProductUpdate.description` переведено на тот же `Optional`-паттерн (`str | None = Field(default=None, ...)`), что и `name`/`category`/`price` — раньше поле объявлялось как обычная строка с дефолтом `""`, не совпадая по форме с остальными полями той же схемы частичного обновления.

## Considered Options

- **Честный `PUT` с обязательным полным телом** — оставить `PUT`, но сделать все поля схемы обязательными и применять их безусловно (без `exclude_unset`), как того требует семантика метода. Отклонено: расширяет обязанность клиента — нужно всегда знать и присылать текущие значения всех полей, включая те, что не меняются, — без выгоды для этого API. Ни один текущий клиент не пользуется полной заменой; частичное обновление уже было основным сценарием использования.
- **Оставить `PUT`, добавить `PATCH` как алиас с тем же поведением** — держать оба метода на одном пути. Отклонено: `PUT`, фактически выполняющий частичное обновление, вводит в заблуждение относительно контракта эндпоинта; два метода с идентичным поведением — источник путаницы без выгоды.

## Consequences

- `PUT /products/{id}` отвечает `405 Method Not Allowed` — любой клиент, использовавший `PUT`, должен переключиться на `PATCH` (в этом сервисе внешних клиентов пока нет).
- Имя обработчика в коде (`update_product`) не меняется — оно и раньше корректно описывало частичное обновление, только HTTP-метод был подобран неверно.
- `ProductUpdate.description` теперь `None`, если не передано в запросе, вместо `""`. Поведение при частичном обновлении не меняется (значение и раньше сохранялось через `exclude_unset`), но тип схемы больше не лжёт о том, что поле обязательно присутствует в теле запроса.
