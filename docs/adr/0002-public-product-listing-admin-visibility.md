# 0002. Публичный доступ к спискам продуктов с полной видимостью только для admin

`GET /products/` и `GET /products/{id}` уже были публичными (без auth-зависимости); `/search`, `/price-range`, `/category/{name}` требовали `CurrentUser`. Вместо унификации в сторону «все защищены» решили сделать все четыре продукт-list-эндпоинта одинаково публичными — продукты являются публичной витриной, доступной без регистрации. Одновременно действует правило: продукты деактивированных владельцев скрыты от всех, кроме `ADMIN` (см. `CONTEXT.md` → «Видимость продуктов деактивированных владельцев»), а значит эндпоинтам всё равно нужно опционально знать роль вызывающего. Для этого вводится новый auth-механизм, которого раньше не было: токен необязателен, но если он передан и невалиден/просрочен/принадлежит деактивированному аккаунту — запрос всё равно завершается ошибкой (401/403), без тихого отката к анонимному просмотру.

## Considered Options

- **Требовать `CurrentUser` везде**, включая ранее публичные `/products` и `/{id}`. Отклонено — ломает уже существующий публичный доступ и противоречит идее витрины без регистрации.
- **Тихий anonymous fallback** при невалидном токене вместо ошибки. Отклонено — везде в проекте невалидный токен является ошибкой, а не поводом для тихой деградации; скрытая деградация замаскировала бы реальные баги клиента.

## Consequences

- Появляется третий auth-паттерн наряду с `CurrentUser`/`AdminUser` — опциональный, но не терпимый к невалидным токенам.
- Мутации (`POST`/`PUT`/`DELETE /products/...`) не затронуты — остаются под `CurrentUser`.
- `/audit` и `/{id}/audit` не затронуты — остаются под `AdminUser` / owner-or-admin.
