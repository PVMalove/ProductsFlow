# 0008. Публичный адрес хранилища — отдельная настройка от внутреннего

Сервис обращается к MinIO для операций с объектами (запись, проверка существования, применение read-политики) по адресу `MINIO_ENDPOINT`; в prod это внутренний Docker Compose адрес контейнера (`http://minio_prod:9000`), недостижимый извне сети сервисов. Публичная ссылка на Картинку товара (см. `CONTEXT.md` → «Картинка товара»), которую получает браузер клиента, не может использовать этот же адрес. Вместо этого вводится отдельная настройка `MINIO_PUBLIC_ENDPOINT`, указывающая на реально достижимый снаружи адрес (в prod — опубликованный на хосте порт MinIO API, `http://localhost:${MINIO_API_PORT_PROD}`). `S3Storage` (`app/storage.py`) принимает оба адреса как отдельные обязательные параметры конструктора: `endpoint_url` — для собственного S3-клиента сервиса, `public_endpoint_url` — только для сборки публичной ссылки (`build_public_url`).

## Considered Options

- **Один и тот же адрес для обеих целей**. Отклонено — в prod внутренний адрес (`minio_prod:9000`) не резолвится вне Docker-сети сервисов; ссылка, отданная клиенту, была бы нерабочей.
- **Вычислять публичный адрес из внутреннего** (подстановкой хоста/порта по правилу) вместо отдельной настройки. Отклонено — само правило преобразования было бы окружение-специфичным (в dev адреса совпадают, в prod различаются и хостом, и портом) и хрупким при любом будущем изменении топологии (домен, TLS, CDN перед хранилищем); явная вторая настройка ничего не предполагает о связи между адресами и не ломается при её изменении.

## Consequences

- В dev оба адреса совпадают (`http://localhost:9002` для обеих переменных в `.env.example`) — различие проявляется только в prod-конфигурации `docker-compose.yml`, где `MINIO_ENDPOINT` указывает на внутреннее DNS-имя сервиса, а `MINIO_PUBLIC_ENDPOINT` — на опубликованный порт.
- Любое окружение, задающее `MINIO_ENDPOINT`, обязано явно задать и `MINIO_PUBLIC_ENDPOINT` — настройки не выводятся друг из друга и не имеют осмысленного дефолта друг для друга.
- Потребовало заодно устранить конфликт портов в prod-профиле `docker-compose.yml`: сервис API и сервис хранилища раньше претендовали на один и тот же внешний порт — API перенесён на порт `9000` (проброшенный на внутренний `8000`), MinIO API — на `${MINIO_API_PORT_PROD:-9004}`, чтобы `MINIO_PUBLIC_ENDPOINT` указывал на реально работающий адрес.
