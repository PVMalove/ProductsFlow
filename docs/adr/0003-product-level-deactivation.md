# 0003. Деактивация товара как отдельное поле, независимое от активности владельца

Добавляем `Product.is_active` — новое, самостоятельное свойство товара, переключаемое владельцем товара или `ADMIN` через `PATCH /products/{id}/activate`/`/deactivate`. Это прямо отменяет утверждение, ранее зафиксированное в `CONTEXT.md` («у `Product` нет и не планируется поля `is_active`») — тогда единственным способом скрыть товар было деактивировать его владельца (см. `CONTEXT.md` → «Видимость продуктов деактивированных владельцев»). Теперь это два независимых, складывающихся механизма скрытия одного и того же товара.

## Considered Options

- **Toggle только `ADMIN`** (по строгой аналогии с `User.is_active`, где деактивировать может только админ). Отклонено — товаром управляет его владелец, и он должен иметь возможность сам скрыть свой товар от других пользователей без участия админа; `ADMIN` добавлен поверх как модерационная возможность, переиспользуя уже существующий owner-or-admin паттерн (`PUT`/`DELETE /products/{id}`).
- **Персонализированная видимость списков** — чтобы владелец видел свой деактивированный товар в `GET /products`/`/search`/`/category`/`/price-range`, потребовалось бы прокидывать `viewer_id` во все list-методы `ProductRepository` и добавлять условие `Product.is_active OR Product.user_id == viewer_id`. Отклонено как более широкий blast radius, чем нужно: прямой доступ по ID уже даёт владельцу способ управлять своим товаром и видеть его.
- **Переиспользовать существующий каскад видимости** (деактивировать владельца целиком вместо отдельного поля товара). Отклонено — деактивация владельца имеет более широкий эффект (блокирует аутентификацию целиком, скрывает вообще все его товары), это не то же самое действие, что «скрыть один конкретный товар».

## Consequences

- Видимость товара теперь определяется двумя независимыми условиями (`Product.is_active` и `User.is_active` его владельца), которые складываются (AND) — см. `CONTEXT.md`.
- У прямого доступа (`GET /products/{id}`) появляется исключение для владельца, которого нет у списков — асимметрия между «посмотреть свой товар по ID» и «увидеть его в общей выдаче», сделанная осознанно ради простоты list-запросов.
- Эта асимметрия не распространяется на деактивацию владельца: деактивированный аккаунт не проходит `get_current_user` вообще, поэтому исключения «владелец всё равно видит своё» для этого случая структурно быть не может.
